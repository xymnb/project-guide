# 本地深知识路由（可选）

Project Guide 的核心规则必须在没有外部知识库时独立可用。本文件只负责把复杂场景按需路由到用户自己的本地知识库。

## 启用条件

仅当 Skill 根目录存在 `project-guide.local.json` 且其中 `enabled: true` 时启用。
本地配置属于机器私有配置，不进入 Git，不进入公开 Skill，也不应复制进报告。

启用后仍先读取当前任务对应的核心 `references/*.md`，再按本文件决定是否需要深读本地知识库。
没有本地配置、路径失效或目标文档缺失时，直接回退到核心 Skill；这本身不是项目 BLOCKED。
## 信息优先级

发生冲突时按以下顺序处理：

1. 当前项目真实文件、Git 状态和本轮可复跑证据。
2. 当前项目的 PROJECT.md、Architecture Baseline、ADR 等项目真相来源。
3. Project Guide 当前运行规则（SKILL.md + references）。
4. 本地深知识库中的方法论、案例和解释。
5. 旧聊天、历史记录和未验证笔记。

本地知识库回答“通常应该怎样管理项目”，不能证明“这个项目现在是什么状态”。
## 路由流程

1. 先判断当前阶段或问题类型。
2. 先读取对应核心 reference。
3. 读取 `project-guide.local.json`，从 `routes` 选择一个最贴近当前问题的 route key。
4. 默认最多读取该 route 的前 2 篇文档；足够回答就停止。
5. 不递归追随 Obsidian wiki 链接，不为了“更完整”扫整个 Vault。
6. 除非用户明确要求研究来源，否则禁止自动进入 `90 原始资料`、原始聊天、JSON/JSONL 或历史导出。
7. 深读后只提取会改变当前判断或执行方法的内容，不把整篇手册搬进项目上下文。
## 推荐 route key

- `kickoff`：新项目立项、产品范围、非技术用户启动。
- `architecture`：架构边界、数据所有权、契约和技术方向。
- `planning`：Milestone、Task Packet、Spike、任务裁剪。
- `coding`：实现循环、调试、验证选择、Git 纪律。
- `acceptance`：测试证据、人工验收、候选版本判断。
- `release`：发布、部署、生产冒烟、恢复方案。
- `change_control`：新需求、范围变化、跨会话恢复、状态漂移。
- `authority`：外部动作、部署、凭据、付费与生产数据权限。
- `templates`：需要生成正式交接、验收或标准指令时才读。
## Fallback 与隐私

- 配置不存在或 `enabled: false`：静默使用核心 Skill。
- 根目录不存在：继续使用核心 Skill；只有当深层资料会实质改变当前决策时，才简短说明“本地深知识库不可用”。
- 某个 route 文件缺失：跳过缺失项，不能凭记忆补写该文档内容。
- 本地知识库默认只读。除非用户明确要求维护知识库，否则不修改 Obsidian 文件。
- 不主动输出本机绝对路径、用户名或知识库中的私人内容。
- 项目验收、测试、部署状态必须来自当前项目证据，不能引用知识库文字冒充事实。
